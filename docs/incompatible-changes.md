# 非互換の変更

Lisp から見える動作のうち、xyzzy 0.2.2.253 から変更したものを記載します。

リポジトリに含まれない Lisp 資産（利用者の `.xyzzy`、`siteinit.l`、第三者製の
site-lisp など）に影響する変更は、必ずここに移行方法とともに記載します。
リポジトリ内で完結する変更は対象外です。

各項目は次の形式で書きます。

```
## 変更の名前

**変更点**: 何がどう変わったか。

**影響**: どういう Lisp コードが影響を受けるか。

**移行方法**: どう書き換えれば動くか。書き換えずに済む回避策があればそれも。
```

----

## バー類のフォントをシステムの設定に従わせた

**変更点**: タブバー・ツールバー・補完リストの文字を、`MS UI Gothic` の 9 ポイント
固定から、システムが設定している UI フォントで描くようにしました。

**影響**: `abbreviate-display-string` は、このフォントの平均文字幅を単位として
長さを数えます。フォントが変わると 1 文字あたりの幅が変わるため、**同じ引数でも
省略される位置が変わり、省略されなくなる場合があります**。

たとえば `MS UI Gothic` では省略されていた次の呼び出しは、平均文字幅がより広い
フォントでは省略されなくなります。

```lisp
(abbreviate-display-string "D:/src/cmigemo-1.3c-MIT/src/wordlist.h" 40 t)
```

**移行方法**: 返る文字列の長さや、省略記号 `...` が含まれることを前提にしている
コードは、その前提を外してください。表示の幅を自分で決めたい場合は、文字数で
切り詰める `abbreviate-string-column` を使ってください。

## 文字幅を担当のフォントに合わせるようにした

**変更点**: ラテン・キリル・ギリシャ・グルジアの文字は半角の升目に並べていますが、
日本語のフォントの多くはこれらを全角の字形で持っています。これまでは一桁に
押し込んでいたため、右半分が切れて読めませんでした。担当のフォントを実測して、
全角の字形しか無い場合は 2 桁として扱うようにしました。

**影響**: `char-columns` の戻り値が、その文字を描くフォントによって変わります。
桁数を数える `count-column`、`current-line-columns`、`abbreviate-string-column`
なども同じ影響を受けます。

既定のフォント `Courier New` はこれらの文字を半角で持つので、フォントの設定を
変えていなければ戻り値は従来と同じです。

**移行方法**: 桁数がフォントに依存しないことを前提にしているコードは、その前提を
外してください。従来どおり常に一桁として扱いたい場合は、共通設定のフォントの
ページで「曖昧な文字幅を半角に固定」にチェックを入れてください。`xyzzy.ini` の
`[Font]` 節の `ambiguousWidth` を `1` にするのと同じです。

この設定では、全角の字形しか持たないフォントを指定していると、字形を横に縮めて
一桁へ収めます。縦横の比が崩れるのが気になる場合は、その文字体系に半角の字形を持つ
フォント（`Courier New` など）を指定してください。

## code-char が範囲外の符号に nil を返すようにした

**変更点**: `code-char` は `char-code-limit` 以上の符号と負の符号に `nil` を
返します。これまでは値を 16 ビットへ切り詰めた文字を返していました。

**影響**: `(code-char 65536)` は `#\NUL` ではなく `nil` になります。範囲外の符号を
渡していたコードは、返った `nil` を文字として扱おうとして型エラーになります。

**移行方法**: 符号を計算して `code-char` に渡す場合は、`char-code-limit` 未満へ
収まることを確かめてください。切り詰めを期待していた場合は
`(code-char (logand n (1- char-code-limit)))` と明示的に書いてください。

## キーを表す文字コードの値を変えた

**変更点**: 機能キー・メタ修飾を表す文字コードを、`#x8000` `#xFE00` `#xFF00` の
区画から `#x200000` 以降へ移しました。移動前の区画は Unicode では漢字・
異体字セレクタ・半角全角形にあたり、文字そのものと衝突するためです。

たとえば `(char-code #\F1)` は `#xFF0F` から `#x20000F` へ、
`(char-code #\M-a)` は `#x8061` から `#x800061` へ変わります。
Shift と Ctrl の修飾が下位バイトの `#x40` `#x80` である点は変わりません。

**影響**: キーを表す文字を `code-char` や数値の直書きで組み立てているコードが
影響を受けます。`#\F1` `#\M-a` のような文字リテラル、`define-key` や
`global-set-key` への文字の受け渡し、`char-code` した値を保存せずに使う分には
影響ありません。

**移行方法**: 数値で組み立てている箇所を文字リテラルへ書き換えてください。
値を設定ファイルなどへ保存している場合は、保存済みの値を作り直してください。

## レジストリに保存した文字列の形式を変えた

**変更点**: `write-registry-literally` が文字列を `REG_BINARY` として書き出すときの
1 文字あたりの大きさが 2 バイトから 4 バイトになりました。内部で文字を保持する
大きさが変わったためです。文字列を CP932 のバイト列として書く `write-registry` は
変わりません。

**影響**: 以前の xyzzy が `write-registry-literally` で書いた値を `read-registry`
で読むと、2 文字が 1 文字に合成された文字列になります。長さの検査は通ってしまうので、
エラーにはなりません。

**移行方法**: `write-registry-literally` で保存した文字列は保存し直してください。
文字列をそのまま読み書きできればよい場合は `write-registry` を使ってください。

## モードラインに言語を表示するようにした

**変更点**: `mode-line-format` の既定値に `%K`（エンコーディングが表す言語）を加えました。
`[utf8n:crlf]` と表示していた箇所が `[utf8n/jp:crlf]` になります。

**影響**: `mode-line-format` を自分で設定していない場合、モードラインの表示が変わります。
設定している場合は変わりません。Lisp の動作に影響はありません。

**移行方法**: 従来の表示に戻すには `.xyzzy` で次のように書いてください。

```lisp
(setq-default mode-line-format "--%*- %b (%M) [%k:%l] %P %f")
```

## バッファの中の文字を Unicode の符号位置にした

**変更点**: 文字を保持する符号を、文字集合ごとに区画を分けた独自のものから、
Unicode の符号位置に変えました。`char-code` と `code-char` が扱う値が変わります。

```lisp
(char-code #\あ)   ; 変更前 33440 (#x82A0)  →  変更後 12354 (#x3042)
```

**影響**: 文字を数値で組み立てたり、数値の範囲で文字種を判定しているコードが
影響を受けます。`(code-char #x82a0)` は「あ」ではなくハングルの音節になります。

漢字を統合したので、日本語・中国語・韓国語で字体の違う漢字が同じ文字になります。
`char=` の結果が変わり、`string=` での突き合わせにも影響します。

**移行方法**: 数値を Unicode の符号位置へ書き換えてください。文字リテラル
（`#\あ`）や文字名（`#\infinity`）で書けるものは、そちらの方が安全です。

## 文字集合ごとの符号を返す関数をやめた

**変更点**: `iso-char-code` と `iso-char-charset` を廃止し、`char-external-code`
を加えました。符号位置には文字集合という区別が無いためです。

`char-external-code` は、その符号で文字がどう書かれるかをバイト列で返します。
2 番目の値は使った符号です。符号を省くと、いま選んでいるバッファのものを使います。

```lisp
(char-external-code #\カ)                    ; → "\x83\x4a", #<encoding sjis>
(char-external-code #\カ *encoding-utf8n*)   ; → "\xe3\x82\xab", #<encoding utf8n>
(char-external-code #\€ *encoding-sjis*)     ; → nil （その符号で書けない）
```

`iso-code-char` は残ります。文字集合の中の符号から文字を作る用途は変わりません。

**影響**: `iso-char-code` と `iso-char-charset` を呼ぶコードはエラーになります。

文字名のうち、文字集合を冠したもの（`#\JISX0208_INFINITY` など）が無くなりました。
素の名前（`#\infinity`）は残ります。

**移行方法**: 符号での書かれ方が要る場合は `char-external-code` を使ってください。
文字集合そのものを知りたい用途は代替がありません。

## バイト列を表す文字列を一文字一バイトにした

**変更点**: 符号変換や base64 が返す「バイト列を表す文字列」で、1 文字が 1 バイトを
表すようになりました。これまでは CP932 の規則で 2 バイトを 1 文字に詰めていました。

```lisp
(length (convert-encoding-from-internal *encoding-sjis* "あ"))   ; 1 → 2
(map 'list #'char-code
     (convert-encoding-from-internal *encoding-utf8n* "あ"))
;; 変更前 (58241 130)  →  変更後 (227 129 130)
```

**影響**: バイト列を `length` で数えたり、`char-code` で 1 文字ずつ取り出している
コードが影響を受けます。`si:octet-length` の戻り値は変わりません。

**移行方法**: バイト列は 1 文字 1 バイトとして扱ってください。これまで
`si:octet-length` が必要だった場面の多くは `length` で足ります。

## バイトコードの形式を変えた

**変更点**: バイトコードを表す特殊形式を `si:*byte-code` から `si:*byte-code-2`
へ改名しました。バイトコードの中の文字が符号位置になり、古い形式をそのまま
実行すると正しくない命令列になるためです。

**影響**: 以前の xyzzy が作った `.lc` は読み込めません。「関数が定義されていません:
system:*byte-code」というエラーになります。

**古い `.lc` が `site-lisp` に残っていると、xyzzy は起動を完了しません。**
起動の途中でエラーの窓が出て止まります。作り直すための xyzzy が起動できないので、
順序が大切です。

**移行方法**: **まず古い `.lc` を `site-lisp` の外へ退けてください。** それから新しい
xyzzy を起動し、`.l` から `byte-compile-file` で作り直します。

```lisp
(dolist (f (directory "site-lisp/" :absolute t :recursive t :wild "*.l"))
  (byte-compile-file f))
```

`.l` が手元に無く `.lc` だけを配布している第三者製のものは、配布元の対応を待つ
必要があります。退けた `.lc` は、元に戻せるよう残しておいてください。

## 符号変換で写せない符号がある

**変更点**: 文字を Unicode の符号位置で保持するようになったため、Unicode に
対応する符号位置が無い符号は読み込めません。これまでは符号によって扱いが
違いましたが、`�`（U+FFFD）一文字に統一しました。Shift_JIS・Big5・ISO-2022 系・
ISO-8859 系・Windows のコードページのいずれも、割り当ての無いバイトが `�` に
なります。

Shift_JIS と Big5 では、2 バイト目を次の文字として読み直すようにしました。
これまでは飲み込んでいたため、`\x82` の直後の改行が消えるなど、後続の文字が
ずれていました。

**影響**: 写せない符号を含むファイルを開くと、その位置が `�` になります。
0.2.2.253 まではこれらのバイトがそのまま保持され、上書き保存で元どおりに
書き戻せる符号もありましたが、保存すると失われます。

そのようなファイルを開いたバッファは、モードラインの符号名に `!` が付き、
`buffer-read-only` が `t` になります。編集するには `toggle-read-only` で
明示的に解除してください。この動作は `*read-only-if-unmappable*` を `nil` に
すると止められます。写せなかった数は `buffer-unmappable-count` で読めます。

**移行方法**: ありません。該当するバイトを含むファイルは、開く前に別の形式へ
変換しておいてください。

## `*unicode-to-half-width*` をやめた

**変更点**: 変数 `*unicode-to-half-width*` を廃止しました。Unicode から内部コードへ
変換するとき、半角と全角のどちらの字を選ぶかを決めるものでしたが、文字を符号位置で
保持するようになり、選ぶ余地が無くなったためです。

**影響**: この変数を `setq` しているコードは「変数が定義されていません」になります。

**移行方法**: 設定を消してください。全角と半角を移し替えたい場合は
`map-to-half-width-string` と `map-to-full-width-string` を使ってください。

## 全角・半角の移し替えで `:greek` と `:cyrillic` が効かなくなった

**変更点**: `map-to-half-width-region` / `map-to-half-width-string` /
`map-to-full-width-region` / `map-to-full-width-string` のキーワード
`:greek` と `:cyrillic` は、指定を受け取るだけで何も変換しなくなりました。
文字を符号位置で保持するようになり、ギリシャ文字とキリル文字には全角と半角の
区別が無くなったためです。

**影響**: これらのキーワードだけを指定した呼び出しは、文字列を変えずに返します。
`:ascii` や `:hiragana` と併せて指定している場合、そちらの変換は従来どおりです。

**移行方法**: ありません。指定を残していても支障はありません。

## `parse-char-encoding-*` が「書ける文字集合」を返すようになった

**変更点**: `parse-char-encoding-region` と `parse-char-encoding-string` が返す
文字集合の意味が変わりました。従来は「その文字が属する文字集合」でしたが、
符号位置には文字集合という区別が無いため、「受け取った文字集合のうち、その文字を
書けるもの」を返すようになりました。

```lisp
(parse-char-encoding-string '(:jisx0208) "漢")   ; → (:jisx0208)
(parse-char-encoding-string '(:big5) "漢")       ; → (:big5)
(parse-char-encoding-string '(:gb2312) "漢")     ; → 0 （簡体字の文字集合には無い）
```

同じ字が複数の文字集合にあるため、以前は落ち着き先の一つしか答えられず、
`:gb2312` だけを渡すと GB 2312 で書ける字まで書けないと答えていました。

**影響**: 戻り値が増えることがあります。渡した文字集合の並びに関わらず、
書ける文字集合が返ります。書けない文字があったときに位置を返す点は同じです。

**移行方法**: 「この文章をこの符号で保存できるか」を知りたい用途はそのまま使えます。
一文字がどの文字集合の出身かを知る用途は、「文字集合ごとの符号を返す関数をやめた」
と同じく代替がありません。

## graphic-char-p がキーを表す文字に nil を返すようにした

**変更点**: `graphic-char-p` は、機能キーやメタ修飾を表す文字に `nil` を返します。
これらの文字コードは `char-code-limit` 以上で、Unicode の符号位置ではないためです。

```lisp
(graphic-char-p #\Right)   ; 変更前 t  →  変更後 nil
(graphic-char-p #\F1)      ; 変更前 t  →  変更後 nil
(graphic-char-p #\M-a)     ; 変更前 t  →  変更後 nil
```

**影響**: 押されたキーが文字かどうかを `graphic-char-p` で見分けているコードが
影響を受けます。0.2.2.253.1 でキーの符号を `#x200000` 以降へ移したとき、この
判定から漏れていました。標準添付の `isearch` とファイラの絞り込みでは、検索中に
矢印キーを押しても命令として働かず、検索文字列にキーの符号が入っていました。
0.2.2.235 と同じ答えに戻ります。

**移行方法**: 通常は不要です。キーを表す文字にも `t` が返ることを当てにしていた
場合は、`(< (char-code c) char-code-limit)` を明示的に書いてください。

## quit が選択範囲も取り消すようになった

**変更点**: `quit`（[C-g]）が、中止するときに `stop-selection` を呼ぶようになりました。

```lisp
(progn (start-selection 2 nil) (goto-char (+ (point) 3))
       (ignore-errors (quit))
       (get-selection-type))   ; 変更前 2  →  変更後 nil
```

**影響**: `quit` を呼んだあとも選択範囲が残ることを当てにしているコードが影響を
受けます。xyzzy の選択はほとんどが一時的なもの（`start-selection` の第 2 引数が
`t`）で、これは命令を挟むと消えるため、[C-g] で消えるように見えていました。
消えないのは永続の選択だけで、[C-g] の振る舞いが選択の種類で割れていました。

**移行方法**: 中止したあとも範囲が要る場合は、`quit` の前に
`(selection-mark)` と `(selection-point)` を控えてください。

## 文字の桁数を East Asian Width と字ごとの実測で決めるようにした

**変更点**: 画面で何桁を占めるかを、従来の文字集合ごとの表ではなく、Unicode の
East Asian Width から決めるようにしました。`W` と `F` の字は常に 2 桁です。
残りは 1 桁の升目に置き、担当のフォントがその字を全角の字形で描くかを**字ごとに
実測**して、全角なら 2 桁へ繰り上げます。

これまでは、同じ字が 1 桁の文字集合と 2 桁の文字集合の両方にあると必ず 1 桁と
していたため、`× ÷ ± ° § ¶ ― ‘ … ′ ← ∞ ─ ○ ■ ♪ ・` などが 1 桁でした。また
従来の文字集合に無い字はすべて 1 桁だったため、CJK 拡張 A の漢字、KS X 1001 に
無いハングル、康熙部首、カタカナ拡張なども 1 桁でした。

あわせて `§ ¨ ° ± ´ ¶ × ÷` を描くフォントを「ラテン」から「日本語」へ移しました。
CP932 にもある記号で、日本語のフォントでは全角に作られているためです。

**影響**: `char-columns` の戻り値が広い範囲で変わります。1 から 2 へ変わるのは
上に挙げた記号と、従来の文字集合に無かった漢字・ハングル・部首です。2 から 1 へ
変わるのは `✁ ➀ Ⓐ ☄ ⅼ` のような、East Asian Width が `N` で日本語のフォントも
字形を持たない絵記号・囲み文字です。

桁数を数える `count-column`、`current-line-columns`、`abbreviate-string-column`
なども同じ影響を受けます。折り返しの位置や、桁を揃える整形の結果が変わります。

**移行方法**: 桁数を控えているコードは `char-columns` から取り直してください。
共通設定のフォントのページの「曖昧な文字幅を半角に固定」は、これまでどおり
ラテン・キリル・ギリシャ・グルジアにだけ効きます。`W` と `F` の字と、日本語の
フォントが担当する字は、この設定でも実測どおりの桁数になります。

## `*kbd-encoding*` が鍵盤入力に効かなくなった

**変更点**: 鍵盤と IME から届く文字を、符号位置としてそのまま受け取るようにしました。

xyzzy の窓はすべて Unicode 窓なので、`WM_CHAR` も `WM_IME_CHAR` も UTF-16 の
符号単位を渡してきます。それを一バイトの外部形式とみなして `*kbd-encoding*` で
復号していたため、**U+0080〜U+00FF の文字が別の字になっていました**。日本語配列では
`*kbd-encoding*` が CP932 なので、`×` (U+00D7) が `ﾗ` (U+FF97) になり、`÷` (U+00F7) の
ように CP932 の先頭バイトと値が重なる字は次の一打を巻き込んで外字になっていました。

**影響**: `*kbd-encoding*` と `*keyboard-layout-list*` の文字符号の指定は、鍵盤入力の
結果を変えません。どちらも A 系の IME が返す確定文字列と再変換にだけ効きます。
`*keyboard-layout-list*` の要素を `nil` にして Unicode 入力を選ぶ指定は、これまでどおり
効きます。

**移行方法**: 配列ごとに文字符号を指定していた場合、その指定は外して構いません。
指定を残しても鍵盤入力の結果は変わりません。
